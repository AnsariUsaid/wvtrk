# Project instructions

## Start of every session
- Read `Requirements/requirements.md` and `Requirements/plan.md` before doing any work.
- Keep them up to date as work progresses: tick off completed items, note decisions, and adjust the plan when scope changes. Commit those updates with the related work.

## UI
- The user decides the UI. Before starting any front-end/UI work, stop and check with the user to agree the design first.

## Commits
- Commit regularly, after every chunk of work is done (a feature, fix, or logical step). Don't let changes pile up.
- Keep commit messages concise: a short summary line (~50–72 chars). Add a brief body only when the change genuinely needs explaining.
